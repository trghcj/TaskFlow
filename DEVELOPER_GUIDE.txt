THE COMPLETE TASKFLOW MASTER GUIDE
Architecture, Development, and Operations Manual

Welcome to the ultimate, comprehensive guide for TaskFlow. This document is a deep-dive manual designed to serve as both a complete product user guide and an exhaustive developer reference. It covers every design decision, architectural flow, codebase structure, and deployment strategy used to build this modern SaaS platform.

====================================================================
PART 1: PRODUCT VISION & USER MANUAL
====================================================================

1.1 THE VISION OF TASKFLOW
TaskFlow was built to solve the modern productivity crisis. Most task managers are either too simple (lacking analytics and strict deadlines) or too complex (requiring days of onboarding). TaskFlow bridges this gap by offering a beautiful, drag-and-drop Kanban interface paired with enterprise-grade features like precise deadline reminders, deep analytics, and multi-provider Single Sign-On (SSO).

1.2 THE KANBAN BOARD (Core Task Management)
The Kanban board is the visual center of the application.
- The Interface: The board is divided into three distinct columns: To Do, In Progress, and Completed.
- Drag & Drop Mechanics: Users can click and hold any task card to drag it across columns. 
- Optimistic UI Updates: When a card is dropped, the frontend immediately updates the visual state before the server responds. This ensures a 0ms latency feel for the user. In the background, the app fires a request to update the task's status in the database. If the server request fails, the UI automatically rolls back.
- Priority Indicators: Tasks are color-coded based on priority (High = Red, Medium = Yellow, Low = Blue) to allow for instant visual triage.

1.3 ADVANCED REMINDERS & THE BACKGROUND SCHEDULER
TaskFlow ensures users never miss a deadline by utilizing a highly precise notification engine.
- Setting Deadlines: When creating a task, users select a specific Due Date and Due Time.
- Reminder Offsets: Users can configure exactly when they want to be notified by choosing an offset (e.g., 15 minutes before, 1 hour before, 1 day before).
- The Notification System: When the exact trigger time is reached, two things happen simultaneously:
  1. In-App Alert: A red badge appears on the Bell icon in the navigation bar. 
  2. Email Digest: A styled HTML email is dispatched to the user's inbox detailing the exact task name, date, and time it is due.

1.4 ANALYTICS & PRODUCTIVITY TRACKING
Data drives productivity. TaskFlow includes a dedicated Analytics dashboard.
- Priority Distribution: A pie chart breaks down the user's active tasks by priority, helping them identify if they are overloaded with High priority items.
- Completion Rates: Bar charts track how many tasks have been completed versus how many remain open.

1.5 COMPREHENSIVE AUTHENTICATION (SSO)
TaskFlow removes friction by offering robust OAuth options.
- Providers: Users can securely log in using Google, GitHub, Microsoft, or Yahoo. Traditional Email/Password is also supported.
- Profile Management: Users can upload custom avatars and update their display names directly from the Settings page.

PART 2: FRONTEND ARCHITECTURE (React & Vite)
====================================================================

The frontend is built for maximum speed, type-safety, and developer velocity.

2.1 CORE TECHNOLOGIES
- React 19 & TypeScript: The entire UI is strictly typed. TypeScript interfaces define exactly what a Task or User object looks like, preventing runtime errors.
- Vite: We use Vite instead of Webpack. Vite uses native ES modules, meaning the local development server starts in milliseconds and Hot Module Replacement updates the browser instantly.
- Tailwind CSS: A utility-first CSS framework. We use classes directly in our TSX files. This ensures design consistency and keeps the bundle size incredibly small.
- Shadcn UI: A collection of highly accessible, beautifully designed components. Shadcn copies the raw source code of its components directly into our project, giving us 100% control over the styling and behavior.

2.2 STATE MANAGEMENT
We completely avoided Redux in favor of a modern, dual-state approach.
- TanStack React Query (Server State): Handles all communication with our backend. It caches API responses, automatically refetches stale data, and handles loading/error states seamlessly.
- Zustand (Local UI State): Handles global state that doesn't belong in the database (e.g., Theme preference, Sidebar toggle state).

2.3 PROGRESSIVE WEB APP (PWA) INTEGRATION
TaskFlow isn't just a website; it's an installable application.
- Installation: Users visiting TaskFlow on Chrome, Edge, Safari, or Android will receive a prompt to "Install App." Once installed, TaskFlow opens in a standalone native window.
- Auto-Updating: The PWA silently downloads new assets in the background when updates are deployed, and seamlessly swaps them in on the next launch.

PART 3: BACKEND ARCHITECTURE (FastAPI & Python)
====================================================================

The backend is built in Python 3.13 using FastAPI, designed to be lightning-fast, highly secure, and deeply integrated with our Postgres database.

3.1 FASTAPI & PYDANTIC
FastAPI uses standard Python type hints to automatically validate incoming JSON requests. If the frontend sends a task creation request without a title, FastAPI automatically rejects it with a 422 Unprocessable Entity error before it ever reaches our logic.

3.2 SQLALCHEMY ORM & ALEMBIC
We interact with our Supabase PostgreSQL database using SQLAlchemy.
- Alembic Migrations: When we change our Python database models (e.g., adding a new column), we run Alembic. It scans the Python code, compares it to the current Postgres schema, and generates a safe SQL script to alter the tables without losing data.

3.3 SECURITY: THE STATELESS JWT AUTH FLOW
TaskFlow does not use traditional session cookies or store passwords. We use a Stateless JWT architecture.
1. The user logs in via Firebase (Google/GitHub/Email). Firebase securely verifies their identity and returns a JSON Web Token (JWT).
2. The frontend attaches this JWT to the header of every API request.
3. Our custom middleware intercepts the request. It uses the firebase-service-account.json credential file to verify the mathematical signature of the JWT directly with Google's public keys.
4. If the signature is valid, the backend safely executes the database query.

3.4 THE BACKGROUND SCHEDULER ENGINE
The most complex logic in the backend is the APScheduler loop that handles due-date reminders.
- The Timezone Challenge: Servers run globally and use UTC natively. However, users input their task deadlines in their local timezones (e.g., IST).
- The Solution: The scheduler wakes up every 5 minutes. It captures the exact current UTC time and explicitly adds the timezone offset for IST. It then performs a perfect string comparison against the user's database entry. If the time matches, it triggers the Resend API to dispatch the email.

PART 4: DEPLOYMENT & INFRASTRUCTURE OPERATIONS
====================================================================

4.1 FRONTEND DEPLOYMENT (Vercel)
Vercel is optimized for Vite and React applications. Vercel deploys the static frontend assets across a global CDN so the app loads instantly from a server physically close to the user.

4.2 BACKEND DEPLOYMENT (Render)
The FastAPI application is deployed as a Web Service on Render.
- The Keep-Alive Ping: Render's free tier aggressively puts applications to "sleep" after 15 minutes of zero incoming HTTP traffic. If the server sleeps, the internal scheduler dies, and reminder emails stop sending.
- The Fix: To prevent this, we configured an external service (cron-job.org) to send a simple HTTP request to the backend URL every 10 minutes. This resets Render's sleep timer, ensuring the server stays awake 24/7.

4.3 DATABASE (Supabase)
Supabase hosts our PostgreSQL instance.
- Connection Pooling: Serverless functions can open hundreds of database connections, crashing Postgres. We use Supabase's Transaction Pooler instead of the direct connection. The pooler multiplexes thousands of requests through a small number of persistent connections, ensuring massive scalability.

PART 5: EXTENDING THE CODEBASE (Developer Tutorials)
====================================================================

TUTORIAL A: Adding a New Database Column
Imagine you want to add a "points" system to tasks for gamification.
1. Open backend/models.py and add the column to the Task class:
   points = Column(Integer, default=0)
2. Run this in your terminal:
   alembic revision --autogenerate -m "Add points to tasks"
3. Apply the Migration to the database:
   alembic upgrade head
4. Open backend/schemas.py and update the Pydantic model so FastAPI allows the new data.

TUTORIAL B: Adding a Custom Domain
When you are ready to launch to the public, you shouldn't use a .vercel.app URL.
1. Purchase a domain from Namecheap or GoDaddy.
2. Go to your Vercel Dashboard > Project Settings > Domains.
3. Type in your new domain (e.g., mytaskflow.com).
4. Vercel will provide an A Record IP address and a CNAME record.
5. Log into your domain provider's DNS settings and paste those exact records in.
6. Within minutes, Vercel will automatically provision a free SSL certificate.

PART 6: TROUBLESHOOTING & COMMON PITFALLS
====================================================================

1. "CORS Error" in Browser Console
- Cause: The frontend is trying to talk to the backend, but the backend doesn't recognize the frontend's URL as "safe".
- Fix: Open backend/main.py. Ensure your exact frontend URL is included in the origins list of the CORSMiddleware.

2. "Firebase ID token has expired"
- Cause: JWTs generated by Firebase expire after exactly 1 hour for security purposes.
- Fix: The Firebase client SDK automatically handles silent token refreshing in the background. Ensure your Axios interceptor is correctly awaiting the token refresh before attaching it.

3. Alembic complains about "Target database is not up to date"
- Cause: You tried to generate a new migration while your local database hasn't applied previous migrations.
- Fix: Always run "alembic upgrade head" before creating new revisions.

PART 7: DEVELOPER Q&A
====================================================================

Q: Why didn't we just use Supabase for Authentication since we use it for the database?
A: While Supabase Auth is great, Firebase Auth currently has much broader, easier-to-integrate support for enterprise SSO providers (like Microsoft and Yahoo) and a simpler React SDK out of the box.

Q: How do we add a new column to the database in the future?
A: 
1. Open backend/models.py and add the column (e.g., phone_number = Column(String)).
2. Run "alembic revision --autogenerate -m 'Add phone number'" in the terminal.
3. Run "alembic upgrade head". Alembic automatically writes and applies the SQL to update Supabase safely!

Q: How does the app update when installed as a PWA?
A: The vite-plugin-pwa is configured with "registerType: 'autoUpdate'". Whenever a new commit is pushed to the repository, Vercel builds the new frontend. The installed PWA detects the new service worker in the background and silently updates itself. The user will see the newest version the next time they launch the app without needing to manually refresh.

Q: If I buy a custom domain, how do I link it?
A: Go to your Vercel project dashboard > Settings > Domains. Add your domain (e.g., taskflow.com). Vercel will give you DNS records (A and CNAME) to paste into your domain registrar (like Namecheap). Vercel will automatically generate a free SSL certificate.

Q: Why do we use cron-job.org to ping the backend?
A: Render's free tier spins down idle apps after 15 minutes. When the app sleeps, the background scheduler dies, meaning scheduled emails won't send. We configured cron-job.org to send a simple HTTP request to the backend every 10 minutes. This resets the sleep timer, ensuring the server stays awake 24/7.
